## T1

[luogu P8162](https://www.luogu.com.cn/problem/P8162)

### 题目描述：

JOI 共和国有 $N$ 个州，编号为 $1 \sim N$。在 2022 年，JOI 共和国将举行总统大选。选举将在每个州分别举行。每个州的获胜者将赢得该州的一张选票。

Rie 将竞选总统，她正计划赢得选举。她决定以发表演讲的方式来提高自己的可靠程度。在她发表演讲后，下列事件可能会发生。

- 如果在第 $i$ 个州的总演讲时间达到了 $A_i$ 小时，她将赢得该州的一张选票。
- 如果在第 $i$ 个州的总演讲时间达到了 $B_i$ 小时，她将获得一名来自该州的协作者。
- 有可能 Rie 在第 $i$ 个州无法获得协作者。此种情况下，$B_i = -1$，否则保证 $B_i > A_i$。

来自第 $i$ 个州的协作者可以在第 $i$ 个州外发表演讲。多个人可以同时在同一个州发表演讲。举个例子，如果两个人在某个州同时发表了 $x$ 小时的演讲，则该州的总演讲时间将增加 $2 x$ 小时。演讲的时间不必是整数个小时。我们可以忽略在两州之间的交通耗时。

大选日快到了，Rie 想要尽快得到 $K$ 张选票。

给定州的数量和每个州的信息，写一个程序计算得到 $K$ 张选票的最小耗时（以小时为单位）。

对于 $100 \%$ 的数据，$1 \le K \le N \le 500$，$1 \le A_i \le 1000$，$A_i \le B_i \le 1000$ 或 $B_i = -1$。

### 题目分析：

第一想法是贪心，按照 $B$ 从小到大排序，然后一一选取，因为选一个 $A$ 在 $B$ 之前肯定是不优的。

但是直接贪心会有问题，当选择一个 $B$，但是他的 $A$ 非常小的时候，那选 $A$ 会让答案变得更优。

设 $B$ 表示选协作者，$A$ 表示只拿票，$C$ 表示什么都不做。

那么你会发现最后排序完的序列，一定是前半段为 $B$ 或者 $A$，后半段为 $C$ 或者 $B$。

可以枚举前半段的长度 $len$，后半段肯定是贪心的选择 $k-len+1$ 个最小的 $A$。

前半部分设 $dp_{i,j}$ 表示选了 $i$ 个点，$j$ 个点是 $B$，转移是简单的。

复杂度 $O(n^3)$。

好像可以 $O(n^2\log n)$，因为你可以发现枚举长度的时候，答案是一个下凸的形式，不过好像可以构造出平台，但如果写的有些瑕疵，还是可以过。

  ```cpp
const double INF=1e18+7;
const int N=500+7;

int n,k,b[N];
double dp[N][N],ans=INF;
struct node{
    int a,b;
}a[N];

bool operator <(const node &a,const node &b){
    if (a.b==b.b) return a.a<b.a;
    return a.b<b.b;
}

void solve(int c){
    for (int i=1;i<=n;i++) b[i]=a[i].a;
    for (int i=0;i<=n;i++)
        for (int j=0;j<=n;j++) dp[i][j]=INF;
    dp[0][0]=0;
    for (int i=1;i<=n;i++){
        for (int j=0;j<=min(c,i);j++){
            dp[i][j]=dp[i-1][j]+1.0*a[i].a/(c+1);
            if (j&&a[i].b!=INF) dp[i][j]=min(dp[i][j],dp[i-1][j-1]+1.0*a[i].b/j);
        }
    }
    for (int i=k;i<=n;i++) ans=min(ans,dp[i][k]);
    for (int i=k;i>=c;i--){
        sort(b+i+1,b+n+1);double sum=0;
        for (int j=i+1;j<=k;j++) sum+=b[j];
        ans=min(ans,dp[i][c]+1.0*sum/(c+1));
    }
}

signed main(){
    scanf("%d%d",&n,&k);
    for (int i=1;i<=n;i++){
        scanf("%d%d",&a[i].a,&a[i].b);
        if (a[i].b==-1) a[i].b=INF;
    }
    sort(a+1,a+n+1);
    for (int i=0;i<=k;i++) solve(i);
    printf("%.10lf\n",ans);
    return 0;
}
  ```

## T2

[luogu P3587](https://www.luogu.com.cn/problem/P3587)

### 题目描述

长度为 $n$ 的一串项链，每颗珠子是 $k$ 种颜色之一。第 $i$ 颗与第 $i-1,i+1$ 颗珠子相邻，第 $n$ 颗与第 $1$ 颗也相邻。

切两刀，把项链断成两条链。要求每种颜色的珠子只能出现在其中一条链中。

求方案数量（保证至少存在一种），以及切成的两段长度之差绝对值的最小值。

对于 $100\%$ 的数据，保证：$2\leq k\leq n\leq 10^6$。

### 题目分析：

设 $st_i$ 表示 $i$ 颜色第一次出现的位置，$ed_i$ 表示 $i$ 颜色最后一次出现的位置，那么这一段肯定要么全选，要么不选。

假设现在的右端点在 $r$，那么对于出现过得颜色有两种情况：

1. $ed_i>r$，那么一定不能选到 $r$ 之前的第一个 $i$ 颜色之前，设为 $lt$，则可以选择的区间为 $[lt+1,r]$，这个可以用可删堆处理，也可以直接用栈做。
2. $ed_i\le r$，那么 $[st_i+1,ed_i]$ 这一段区间一定不能作为左端点，可以给这个区间打上标记，然后和上面的区间做一个合并，可以用线段树做，支持区间加，区间求和。

这样第一问就求完了，第二问你考虑贪心的去选，肯定是在 $[lt,i]$ 中最接近 $r-\frac{n}{2}$ 的位置，也可以用线段树求。

**注意**，右端点不能取到 $n$，否则对于 $[1,x]$ 和 $[x+1,n]$ 这样的划分，会被计算两次。

### 代码：

<details>
  <summary> 点击查看代码 </summary>


  ```cpp
const int INF=1e9+7;
const int N=1e6+7;

int n,k,a[N];
int st[N],ed[N];
int stk[N],top;
bool vis[N];
int sum=0,ans=INF;

namespace SG{
    struct node{
        int l,r;
        int sum,tag;
    }t[N<<2];
    void pushup(int p){
        t[p].sum=t[ls(p)].sum+t[rs(p)].sum;
    }
    void add(int p,int k){
        t[p].sum=(t[p].r-t[p].l+1)*k;
        t[p].tag=k;
    }
    void pushdown(int p){
        if (!t[p].tag) return;
        add(ls(p),t[p].tag);
        add(rs(p),t[p].tag);
        t[p].tag=0;
    }
    void build(int l,int r,int p){
        t[p].l=l,t[p].r=r,t[p].sum=t[p].tag=0;
        if (l==r) return;
        int mid=(l+r)>>1;
        build(l,mid,ls(p)),build(mid+1,r,rs(p));
        pushup(p);
    }
    void modify(int ql,int qr,int l,int r,int p,int k){
        if (ql<=l&&qr>=r) return add(p,k),void();
        int mid=(l+r)>>1;pushdown(p);
        if (ql<=mid) modify(ql,qr,l,mid,ls(p),k);
        if (qr>mid) modify(ql,qr,mid+1,r,rs(p),k);
        pushup(p);
    }
    int query(int ql,int qr,int l,int r,int p){
        if (ql<=l&&qr>=r) return t[p].sum;
        int mid=(l+r)>>1,sum=0;pushdown(p);
        if (ql<=mid) sum+=query(ql,qr,l,mid,ls(p));
        if (qr>mid) sum+=query(ql,qr,mid+1,r,rs(p));
        return sum;
    }
    int find(int ql,int qr,int l,int r,int p,int pos){
        if (t[p].sum==(r-l+1)) return -1;
        if (l==r) return l;
        int mid=(l+r)>>1;
        if (mid>qr) return find(ql,qr,l,mid,ls(p),pos);
        if (mid<ql) return find(ql,qr,mid+1,r,rs(p),pos);
        if (mid+1<=pos){
            int tmp=find(ql,qr,mid+1,r,rs(p),pos);
            if (~tmp) return tmp;
            return find(ql,qr,l,mid,ls(p),pos);
        }
        else{
            int tmp=find(ql,qr,l,mid,ls(p),pos);
            if (~tmp) return tmp;
            return find(ql,qr,mid+1,r,rs(p),pos);
        }
    }
}using namespace SG;

signed main(){
    scanf("%lld%lld",&n,&k);
    for (int i=1;i<=n;i++) scanf("%lld",&a[i]);
    build(1,n,1);
    for (int i=1;i<=n;i++) ed[a[i]]=i;
    for (int i=n;i>=1;i--) st[a[i]]=i;
    stk[top=1]=0;
    for (int i=1;i<n;i++){
        stk[++top]=i;
        int col=a[i];
        if (ed[col]==i){
            vis[col]=1;
            if (st[col]<ed[col]) modify(st[col]+1,ed[col],1,n,1,1);
        }
        while(vis[a[stk[top]]]) top--;
        int lt=stk[top]+1;
        if (lt>i) continue;
        int tmp=query(lt,i,1,n,1);
        sum+=(i-lt+1)-tmp;
        int need=max(1ll,i-(n>>1));
        int S=find(lt,i,1,n,1,need);
        if (S==-1) continue;
        ans=min(ans,abs(i-S+1-(n-(i-S+1))));
    }
    printf("%lld %lld\n",sum,ans);
    return 0;
}
  ```

## T3

[luogu P6235](https://www.luogu.com.cn/problem/P6235)

### 题目描述：

Srečko 想给一个 $m$ 行（从 $0$ 至 $m-1$ 编号） $n$ 列（从 $0$ 至 $n-1$ 编号）的的矩形网格的每一个格子染上色。一开始，整个矩形都是白色的。每一步，他都会选择一条对角线，并给这条对角线上的所有格子染上色。每个对角线染色都需要一定的费用（忽略长度），这就导致某些对角线的染色费用有高于其他某些对角线。

你需要写一个程序，读入各个对角线的染色费用，求出将所有格子染上色的最小总费用。

**注意，同一个格子被重复多次地染色是被允许的。**

---

一个 $m$ 行 $n$ 列的矩形网格共有 $2n+2m-2$。

例：当 $m=4,n=3$ 时，共有 $12$ 条对角线：

![e.g.](https://cdn.luogu.com.cn/upload/image_hosting/j74h8wgo.png)

输入共 $3$ 行。

第一行：两个整数 $n,m$；

第二行：共 $m+n-1$ 个整数，描述所有 $\searrow$ 方向的对角线。第 $1$ 个整数表示 $(0,n-1)$ 这个单个的格子，第 $2$ 个整数表示 $(0,n-2),(1,n-1)$ 两个格子，以此类推。

第三行：共 $m+n-1$ 个整数，描述所有 $\nearrow$ 方向的对角线。第 $1$ 个整数表示 $(0,0)$ 这个单个的格子，第 $2$ 个整数表示 $(0,1),(1,0)$ 两个格子，以此类推。

对于所有数据，保证 $1\le m,n\le 2\times 10^5$，每条对角线的染色费用 $\in [1,10^9]$。

### 题目分析：

你发现把整个长方形转过来就相当于给你一个有行有列的不规则图形，可以用网络流去做，唯一的难点就是要计算一条线被多少条线经过，这样可以得到 $60$ 分的高分。

发现可能会出现规律，当 $n=m$ 的时候，每次经过斜线的边会多 $2$，可以用前缀和优化建图，能得到 $80$ 分，感觉已经非常不错了。

但是中间会出现 $[2,6]$，$[3,7]$，$[4,8]$ 这样的范围，发现完全不可优化，但是好像有老哥用 $dp$ 优化出来了，感觉很牛。

你发现这个图还有一些性质没有挖掘，这个图黑白染色完之后，两两不互相影响，考虑从网络流的角度入手这个问题，我们每次选取最紧的一个区间去增广，也就是右端点最小的，然后每次贪心的流。

能贪心流也就意味着不会出现推流这种操作，假设会出现推流的操作，如果出现退流一定是往左推，那么也就说明退到的那个位置，一定右边是没有流满的，右边没有流满意味着左边因为流空了，但是退流一定是后面这个点往前推的，说明后面存在流，但是左边没有流了，右边怎么会有流，所以出现矛盾，因此不会出现退流的操作。

直接暴力还是 $O(n^2)$ 的，但是发现一个地方流满了，就不会再流第二次，所以用个并查集和后面一个点合并即可，由于一次增广至少流空一个位置，所以复杂度为 $O(n\log n)$。

  ```cpp
const int INF=1e9+7;
const int N=4e5+7;

int n,m,val[N],fa[N];
pair<PII,int>a[N];

bool cmp(pair<PII,int> &a,pair<PII,int> &b){
    return a.fi.se<b.fi.se;
}

int find(int x){
    if (x==fa[x]) return x;
    return fa[x]=find(fa[x]);
}

signed main(){
    cin>>n>>m;
    for (int i=1;i<n+m;i++){
        cin>>a[i].se;
        a[i].fi.fi=max(1ll,max(m-i+1,i-m+1));
        a[i].fi.se=min(min(n*2+m-i-1,i+m-1),n+m-1);
        if ((a[i].fi.fi^(i+m+1))&1) a[i].fi.fi++;
        if ((a[i].fi.se^(i+m+1))&1) a[i].fi.se--;
    }
    sort(a+1,a+n+m,cmp);
    for (int i=1;i<n+m;i++) cin>>val[i];
    int ans=0;
    for (int i=1;i<=n+m+1;i++) fa[i]=i;
    for (int i=1;i<n+m;i++){
        int l=find(a[i].fi.fi),r=a[i].fi.se;
        while(l<=r&&a[i].se){
            int cur=min(a[i].se,val[l]);
            a[i].se-=cur,val[l]-=cur;
            ans+=cur;
            if (!val[l]) fa[l]=find(l+2);
            l=find(l+2);
        }
    }
    printf("%lld\n",ans);
    return 0;
}
  ```
