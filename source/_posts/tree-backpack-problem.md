## 题目描述：

松鼠王国有 $n$ 个城市，城市与城市之间有道路相连，有 $n-1$ 条道路，保证任意两个城市连通。每条道路都有边权。

现在，每个城市都贮存了一些松果。将 $x$ 个松果从 $u$ 城市运送到 $v$ 城市的代价为 $x\times dist(u,v)$，其中 $dist(u,v)$ 为 $x$ 城市到 $v$ 城市的距离，定义为从 $u$ 城市到 $v$ 城市最短路径的边权之和。国王想要通过以一定的方式运输这些松果，使得每个城市最后的松果数尽可能**平均**。即是每个城市松果数的**方差**尽可能小。 

求最小的运输代价，使得每个城市松果数的**方差**最小。

对于 $100\%$ 的数据，有：$T\le 5$，$n\le 5000$，$a_i,w_i\le 10000$。

## 题目分析：

读完题发现一头雾水，感觉有点像网络流，细细构造发现好难（当然可以用网络流）。

考虑去发现一些题目中给到的性质：

- 加入说 $u$ 送到 $v$ 要经过 $lca$，那么 $u$ 把东西放在 $lca$，再让 $lca$ 送到 $v$，最后的代价是一样的，也就是说不会出现把东西放在某一个位置，后来再运走的情况。
- 假如一颗子树中的最终松果个数固定了，那么当前点 $u$ 到 $fa$ 这条路造成的贡献必然是 $|最终子树内松果个数-目前子树内松果个数| * w$。

通过题意你可以知道最后每个点的松果个数必然是 $ave$ 或者是 $ave+1$（这里的 $ave$ 指平均值）。

再往下就很好做了，设 $dp_{i,j}$ 表示 $i$ 个点里面放 $j$ 个 $ave+1$ 的最小代价。

发现每一个子树的根节点是否为 $ave+1$ 没法转移，但是其实不需要管，因为如果子树内每一个点的状态都固定以后，根的状态也就固定了。

用一个树上背包解决即可，复杂度为 $O(n^2)$。

  ```cpp
const int INF=1e18+7;
const int N=7e3+7;

int dp[N][N],g[N];
int n,a[N],sz[N],val[N],res,ave;
vector<PII> G[N];

void dfs(int u,int fa){
    sz[u]=1;val[u]=a[u];
    dp[u][0]=dp[u][1]=0;
    for (auto s:G[u]){
        int v=s.fi,w=s.se;
        if (v==fa) continue;
        dfs(v,u);
        for (int i=0;i<=res;i++) g[i]=INF;
        for (int i=0;i<=min(sz[u],res);i++){
            for (int j=0;j<=sz[v]&&i+j<=res;j++){
                g[i+j]=min(g[i+j],dp[u][i]+dp[v][j]+w*abs((sz[v]*ave+j-val[v])));
            }
        }
        for (int i=0;i<=res;i++)
            dp[u][i]=g[i];
        sz[u]+=sz[v];val[u]+=val[v];
    }
}

void init(){
    res=0;
    for (int i=1;i<=n;i++){
        G[i].clear();
        sz[i]=val[i]=0;
    }
    memset(dp,0x3f,sizeof dp);
}

void Main(){
    scanf("%lld",&n);
    init();
    for (int i=1;i<=n;i++) scanf("%lld",&a[i]),res+=a[i];
    ave=res/n;res=res%n;
    for (int i=1;i<n;i++){
        int u=read(),v=read(),w=read();
        G[u].p_b(m_p(v,w));G[v].p_b(m_p(u,w));
    }
    dfs(1,0);
    printf("%lld\n",dp[1][res]);
}

signed main(){
    int T=read();
    while(T--) Main();
    return 0;
}
  ```

## 复杂度分析：

当时我怎么看我的复杂度都是 $O(n^3)$，但是没想到其实树上背包的复杂度是 $O(n^2)$ /kt。

树上背包的复杂度卡紧了是 $O(nm)$ 的。

以下给两种证明：

1. 对于一对点 $u,v$，统计他俩答案的位置只有 $LCA(u,v)$，所以说每个点对只会被统计一次，并且一个的贡献是 $O(1)$ 的，那么总复杂度为 $O(n^2)$。（这种应该是**感性理解**的方式）

2. $n$ 为节点个数，$m$ 为背包大小。

   考虑合并两个背包的复杂度为 $O(s_1s_2)$，$s_1$ 为第一个背包的大小，$s_2$ 为第二个背包的大小，但这个复杂度是在背包容量未达到上限的情况下。

   而在树上背包中，容量是有上限的，实际上是把 $n$ 个节点合并到一个背包的过程，显然合并的总次数是 $O(n)$ 的。

   合并过程中复杂度显然和 $s_1,s_2,m$ 有关，并且 $s_1,s_2\le m$，现在复杂度为：
   $$
   O(\min(s_1+s_2,m)\times \min(s_1,s_2))
   $$
   之所以有这个式子是因为我们需要枚举合并完背包大小为多少，在枚举小的那一个背包的大小。

   在实际操作中，是不需要管背包的大小的，设 $i$ 为最终背包大小，$j$ 为第一个背包大小，只要保证 $i-j$ 小于等于另一个背包的大小即可。

   我们对 $s_1$ 和 $s_2$ 的大小进行分类讨论。

   当 $s_1=m,s_2=m$，容易发现这种合并不会超过 $\frac{n}{m}$ 次，每次合并复杂度为 $O(m^2)$ 的，总复杂度为 $O(nm)$。

   当 $s_1<m,s_2<m,s_1+s_2\ge m$，这种情况下合并次数也不会超过 $\frac{n}{m}$ 次，每次合并复杂度为 $O(m^2)$，总复杂度为 $O(nm)$。

   设 $s_1<m,s_2<m,s_1+s_2<m$，考虑把 $m$ 个点合并成一颗大小为 $m$ 的树，复杂度为 $O(m^2)$，但是这样的树的个数不会超过 $\frac{n}{m}$ 个，所以总复杂度为 $O(nm)$。

   综上，复杂度为 $O(nm)$。
